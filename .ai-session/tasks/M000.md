# M000 — Full Baseline Audit

## WHY

Arkiba has accumulated working components, prototypes and integrations across multiple development phases. Before the next major build phase, establish exactly what is real, what is simulated, what is unsafe, what should be preserved, and what should be replaced.

## SCOPE

Audit without intentionally changing product behavior:

- architecture;
- frontend;
- backend;
- database/persistence;
- authentication;
- authorization;
- tenant isolation;
- file/storage model;
- jobs/queues/schedulers;
- telephony;
- SMS;
- Intake;
- document generation;
- Doctolib;
- EMED;
- Stripe/billing;
- deployment;
- infrastructure;
- monitoring/logging;
- secrets/configuration;
- mocks/stubs/hard-coded demo paths;
- dead code and duplication;
- test coverage;
- CI/CD;
- performance and appointment-to-call latency path;
- UX and responsive behavior.

Also inspect the separate ArkenDu77/arkiba-intake repository as a dependency/subsystem and document its relationship to the primary repository.

## OUT OF SCOPE

- broad visual redesign;
- new product features;
- major refactors;
- architecture migrations;
- production data migration.

Critical security findings may be documented immediately but should become dedicated P0 tasks rather than being silently changed during M000.

## REQUIRED OUTPUTS

Update:
- .ai-session/ARCHITECTURE.md
- .ai-session/STATE.md
- .ai-session/SECURITY_MODEL.md where evidence changes assumptions
- .ai-session/BACKLOG.yaml

Create evidence-backed inventories for:
- real integrations;
- mocked/simulated integrations;
- external blockers;
- security findings;
- tests and missing tests;
- performance bottlenecks;
- UX/responsive problems.

Classify each major subsystem:
KEEP / REFACTOR / REPLACE / DELETE / BUILD.

## ACCEPTANCE

M000 is complete only after:
1. Astra produces the baseline.
2. Builder independently reproduces/validates important technical findings.
3. Reviewer challenges the baseline and checks for material omissions.
4. All three agree on a reconciled P0/P1/P2 backlog.
5. No product behavior was intentionally changed as part of the audit.
